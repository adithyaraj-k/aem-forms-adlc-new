# AEM Adaptive Forms — Agent Skills

AI coding agent skills for AEM Adaptive Forms development on AEM as a Cloud Service.
Works with Cursor, GitHub Copilot, Claude Code, and any IDE that supports agent skills.

---

## What is this?

Each folder is a **skill** — a markdown file that teaches your AI coding assistant
how to generate correct, production-ready AEM Adaptive Forms code. No custom backend.
No plugins. Just drop the skill folders into your project and start prompting.

---

## Skills included

| Skill | What it generates | Start here? |
|---|---|---|
| `ensure-forms-agents-md` | `AGENTS.md`, `CLAUDE.md`, `.aem-forms-config.yaml` — project bootstrap | **Yes — run first** |
| `generate-schema` | Form data schema (JSON Schema / XSD) with FDM-ready bindings from NL, OpenAPI, AF XML, or Figma | Run before `create-adaptive-form` |
| `create-adaptive-form` | Complete form XML (fields, panels, wizard, layout, validation) | |
| `create-form-rules` | Rule editor JSON (show/hide, validate, calculate, cascade) | |
| `create-form-component` | Custom field component (Sling Model, HTL, dialog, clientlib) | |
| `create-submit-action` | Submit action OSGi service + JCR node + config + unit test | |
| `create-prefill-service` | Prefill service OSGi + config + system user mapping + unit test | |
| `create-form-theme` | LESS/CSS theme with full AEM Forms token system | |
| `create-form-tests` | JUnit 5 unit tests + Selenium rule editor integration tests | |

## Quick start

**Step 1 — Run the bootstrap skill first (once per project)**

```
Run the ensure-forms-agents-md skill on this project
```

The agent will read your `pom.xml`, detect whether you use Core Components or
Foundation, check for FDM, and generate `AGENTS.md` and `.aem-forms-config.yaml`.

---

**Step 2 — Create your first form**

```
Create a Contact Us form with:
- Full Name (text, required)
- Email (email, required)
- Phone (tel, optional)
- Subject (dropdown: General / Billing / Support / Other, required)
- Message (textarea, required, min 20 characters)
- File attachment (PDF or image, optional, max 5 MB)
Submit to REST endpoint /api/v1/contact
```

---

**Step 3 — Add business rules**

```
Add a rule to the contact form:
Show the "File Attachment" field only when Subject is "Billing" or "Support"
```

---

**Step 4 — Create a submit action**

```
Create a custom submit action called RestApiSubmitAction that:
- Posts form data as JSON to the endpoint in the OSGi config
- Uses a Bearer token from the OSGi secret config
- Logs errors and returns a user-friendly message on failure
```

## Example prompts

**Loan application wizard:**
```
Create a Home Loan Application form with 3 wizard steps:
Step 1 - Personal Info: Full Name, Date of Birth, PAN Number, Marital Status
Step 2 - Employment: Type (dropdown), Company Name, Monthly Income
Step 3 - Loan Details: Amount, Tenure, Property Location, Upload ID Proof
Submit to /api/v1/loan/apply
```

**Show/hide rules:**
```
Add rules to the loan form:
- Show Company Name only when Employment Type is Salaried or Self-Employed
- Show Guarantor panel when Loan Amount exceeds 50,00,000 AND experience < 2 years
- Make Spouse Name required when Marital Status is Married
```

**Custom prefill:**
```
Create a prefill service called CustomerProfilePrefillService that:
- Fetches the logged-in user's profile from /api/v1/customer/{userId}
- Maps firstName, lastName, email, phone, and address fields
- Returns empty data gracefully for anonymous users
```

**Custom submit:**
```
Create a submit action called CrmSubmitAction that:
- Posts form JSON to the CRM API endpoint from OSGi config
- Triggers workflow /var/workflow/models/form-review on successful submission
- Sends a confirmation email to the submitter's email field
```

## Troubleshooting

| Issue | Solution |
|---|---|
| "Skill not recognised" | Verify skill folder is at correct IDE path (`.cursor/skills/` not `.cursor/rules/`) |
| Wrong component resource types | Run `ensure-forms-agents-md` to regenerate `AGENTS.md` — it sets the correct type |
| Generated code has wrong Java package | Check `.aem-forms-config.yaml` → `package` value matches your project's base package |
| Form does not appear in editor | Verify `ui.content` module path and run `mvn clean install -PautoInstallSinglePackage` |
| Submit action not in form dialog | Check JCR node path matches `getServiceName()` return value exactly |
