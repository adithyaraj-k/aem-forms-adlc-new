# Skill: ensure-forms-agents-md

## Role

You are a project detective. You read existing project files to understand the
project structure, then write `AGENTS.md` and `CLAUDE.md` so every other skill
in this repository is project-aware from the first prompt.

This skill runs ONCE per project. If `AGENTS.md` already exists at the repo root,
do nothing and tell the developer it already exists.

---

## Trigger

This skill activates when the developer asks to:
- Set up AEM Forms agent skills on this project
- Initialise the AI assistant for this Forms project
- "Run the bootstrap skill"
- Generate AGENTS.md for an AEM Forms project

---

## Step 1 — Detect project settings

Read each of these files and extract the values listed:

### From `pom.xml` (root)

```xpath
/project/groupId              → {groupId}
/project/artifactId           → {artifactId}
/project/version              → {projectVersion}
/project/parent/artifactId    → determines if AEMaaCS ("aem-project-archetype")
                                or AEM 6.5 ("uber-jar" dependency present)
```

Detect Java package by reading:
```xpath
/project/properties/app.id      (if present)   → {appId}
```
Or read `core/pom.xml`:
```xpath
/project/groupId + "." + /project/artifactId   → base Java package
```

### From `ui.apps/src/main/content/jcr_root/apps/` (scan directory)

The first subdirectory name = `{projectName}` (e.g. `wknd`, `mysite`)

### Detect Core Components vs Foundation

Search for any file under `ui.apps/.../components/` or `ui.content/.../forms/`:
- Contains `sling:resourceType="core/fd/components/form/..."` → **Core Components**
- Contains `sling:resourceType="fd/af/components/..."` → **Foundation Components**
- No forms found → **Not yet created** — default to Core Components for new projects

### Detect FDM

Check if any of these paths exist:
- `/conf/global/settings/cloudconfigs/fdm/` in `ui.content`
- Any `.content.xml` containing `sling:resourceType="fd/fdm/gui/components/..."`

→ `fdmEnabled: true` if found, else `false`

### Detect existing themes

Scan: `ui.apps/src/main/content/jcr_root/apps/{projectName}/fd/af/themes/`
→ List each subdirectory as an available theme

### Detect existing submit actions

Scan: `ui.apps/src/main/content/jcr_root/apps/{projectName}/fd/af/submitactions/`
→ List each subdirectory as an available submit action

## Step 2 — Create .aem-forms-config.yaml

If this file does not exist at the project root, create it:

```yaml
# AEM Adaptive Forms Agent Configuration
# Auto-generated by ensure-forms-agents-md skill
# Edit values to match your project if auto-detection was incorrect

configured: true

project: "{projectName}"
package: "{javaBasePackage}"
group: "{projectName|titleCase} Forms"
aemVersion: "{cloud|6.5}"
formType: "{coreComponents|foundation}"
fdmEnabled: {true|false}
fdmRoot: "/conf/global/settings/cloudconfigs/fdm"
defaultTheme: "{detectedThemePath|/libs/fd/af/themes/canvas}"
submitActionPackage: "{javaBasePackage}.forms.submit"
prefillServicePackage: "{javaBasePackage}.forms.prefill"
formsContentRoot: "/content/forms/af"
# damContentRoot is ALWAYS derived from {project} — the folder segment under
# /content/forms/af/, /content/dam/formsanddocuments/, and /conf/forms/ is {project},
# never a separate hardcoded app folder. This keeps a form's DAM guide-asset path
# (/content/dam/formsanddocuments/{project}/{formName}) matched to its form path.
damContentRoot: "/content/dam/formsanddocuments/{projectName}"
```

|----------------|--------------------------------------------------|----------------------------------|

| ui.config      | ui.config/src/main/content/jcr_root/apps/        | OSGi configs per runmode         |

| Asset type         | Path                                                          |
|--------------------|---------------------------------------------------------------|

| Themes             | /apps/{project}/fd/af/themes/{themeName}/                     |
| Prefill services   | core/src/main/java/{package}/forms/prefill/                   |
| Submit action Java | core/src/main/java/{package}/forms/submit/                    |

## Available skills

The following skills are installed in this project. Use them by name in prompts.

| Skill                    | Use when you need to...                                       |
|--------------------------|---------------------------------------------------------------|
| create-adaptive-form     | Scaffold a new form with fields, layout, panels               |
| create-form-rules        | Add show/hide, validate, calculate, or cascade logic          |
| create-form-component    | Build a custom field type not in Core Components              |
| create-submit-action     | Create a custom submit handler (REST, email, workflow)        |
| create-prefill-service   | Pre-populate form fields from an API or JCR                   |
| create-form-theme        | Brand forms with project design tokens                        |
| create-form-tests        | Generate unit and integration tests for Forms services        |

## Forms type: {Core Components | Foundation}

{IF CORE COMPONENTS:}
This project uses **AEM Forms Core Components** (recommended for AEMaaCS).
- All `sling:resourceType` values start with `core/fd/components/form/`
- Never use Foundation component resource types (`fd/af/components/`)
- Form container: `core/fd/components/form/container/v2/container`

{IF FOUNDATION:}
This project uses **Foundation Adaptive Forms** components (legacy).
- All `sling:resourceType` values start with `fd/af/components/`
- Core Components resource types must NOT be used
- Form container: `fd/af/components/container/v2/container`

## FDM status: {Enabled | Disabled}

{IF ENABLED:}
Form Data Model is configured. FDM root: `{fdmRoot}`
- Use `fd:formDataRef` attributes on fields for data binding
- FDM service invocations available in rule editor via `INVOKE_SERVICE`

{IF DISABLED:}
FDM is not configured. Forms use direct REST submit actions.
- Do not generate `fd:formDataRef` bindings
- Use custom submit actions for API integration

{list each detected theme path}

## Build and deploy

```bash
# Build and deploy all modules to local AEM SDK
mvn clean install -PautoInstallSinglePackage

# Deploy only ui.apps (faster for component changes)
mvn clean install -PautoInstallPackage -pl ui.apps

# Run unit tests only
mvn test -pl core
```

## Common mistakes to avoid

- **NEVER** use Foundation component resource types in a Core Components project
- **NEVER** hardcode `/content/forms/af/` paths — use variables from config
- **NEVER** leave ResourceResolver open — always use try-with-resources
- **NEVER** hardcode secrets in `.cfg.json` — use `$[secret:keyName]`
- **ALWAYS** set `aria-label` on every form field
- **ALWAYS** include both OSGi service AND JCR node for custom submit actions
```
